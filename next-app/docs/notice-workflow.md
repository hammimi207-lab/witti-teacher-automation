# 알림장 작성 흐름 및 확인 사항

## 실제 앱 위치

현재 서비스 개발 코드는 `next-app/`의 Next.js App Router 앱이다. UI는 `src/features/records/record-wizard.tsx`, 생성·저장·Word 내보내기는 `src/app/api/records/`에 있다. 저장은 기존 Supabase `play_sessions`, `generated_texts`와 비공개 사진 저장소를 사용한다. Streamlit 코드는 수정하거나 연동하지 않았다.

GitHub main에는 이 앱의 기반 코드가 없었으므로 이번 PR에 실행 가능한 기존 Next.js 앱 파일도 처음 등록한다. 기존 문장 순서 편집 코드를 유지한다. 로컬 `.env.local`, `.vercel`, 의존성, 빌드 산출물, 백업, 과거 버전, QA 사진은 커밋하지 않는다.

## 구현

- 작성일(한국 기준 오늘, 변경 가능)·아동 별칭 → 일상·놀이·활동 자유 관찰 → 전체 공지 → 생성 → 미리보기·문장 순서·전체 글 편집 → 서두·마무리 인사 선택·수정·적용 → 저장·Word 다운로드.
- 인사는 생성 이후 결과 아래 두 카드에서 선택한다. 적용 버튼을 누를 때에만 최종 글의 처음과 끝에 반영하며, 재적용 시 이전에 적용한 인사를 교체한다. 저장과 Word는 이 최종 글을 그대로 사용한다.
- 공지는 전달받은 안내를 그대로 붙여 넣고 적용하는 입력란을 기본으로 제공한다. 저장 공지 불러오기와 재사용 양식의 제목·분류 입력은 선택할 때만 펼친다. 이번 공지의 날짜와 본문은 자동 변환하지 않으며, 자리표시자 변환은 재사용 양식을 저장할 때만 수행한다.
- 알림장은 자세한 서술 하나로 생성한다. 해석과 원 내 지원을 필수로 요구하지 않는다. 짧은 사실은 짧게 전달하고, 빈 영역·미입력 행동·발화·감정·발달 평가·시간을 만들지 않도록 생성 지침을 제한했다. 실제 모델 결과는 교사가 확인한다.
- 놀이 이야기에서 알림장으로 전환할 때 현재 아동의 관찰을 놀이 영역으로 이어받는다. 아동을 바꾸면 개인 관찰·해석·지원·사진·결과는 비운다. 반 공통 활동·공지·인사는 재사용한다. 공통 활동의 브라우저 저장 키는 계정과 작성일별로 구분한다. 반을 별도로 선택하는 기존 모델은 없으므로 기관 전체나 다른 교사와 공유 범위를 확대하지 않는다.
- 공지 칩은 여러 개 선택·해제할 수 있다. 이번 문구는 선택한 양식의 복사본이다. 수정 후 ‘이번 공지에 적용’을 누르고, 적용하지 않은 수정과 미완성 자리표시자는 생성 전에 안내한다. 같은 공지 본문은 중복 조합하지 않는다.
- ‘공지 양식으로 저장’은 제목·분류·본문으로 새 양식을 만든다. 원본 수정·삭제는 별도 메뉴다. 날짜·시간·과거 아동 별칭은 재사용 시 자리표시자로 바꾸고, 양식 저장 시 ‘준비물: / 장소: / 내용:’ 값도 자리표시자로 바꾼다. 자연어로만 쓰인 변수는 교사가 직접 `{{날짜}}`, `{{시간}}`, `{{장소}}`, `{{준비물}}`, `{{내용}}`으로 편집할 수 있다.
- 인사는 사용 안 함을 포함해 각각 선택하고 후보를 수정한다. 작성일을 변경하면 후보·추천을 다시 계산하며 교사의 기존 선택 문구를 자동으로 덮어쓰지 않는다.
- 모델은 관찰 본문만 생성하고, 서버가 선택한 서두·공지·마무리를 한 번 조합한다. 공지는 `【전체 공지】`로 구분하고 마무리는 끝에 둔다. 생성 후에는 `result.finalNotice`가 유일한 최종본이다. 미리보기·저장·Word에서 인사/공지를 다시 붙이거나 문장 순서를 재계산하지 않는다.
- 기존 버전 1 기록과 일반 텍스트 기록은 계속 조회·다운로드 가능하다. 옛 입력 필드는 보존하고 작성 중 임시 저장만 세 영역으로 변환한다. 이미 편집한 결과와 저장 당시 입력은 변환하지 않는다.

## 원문 검색 범위와 한계

학습용 업로드 원문·벡터 검색·학습 자료 인덱스를 조회하는 저장소나 코드가 없다. 학습된 모델이 원문을 검색할 수 있다고 가정하지 않았다. 교사 자신의 등록 공지 양식과 최근 저장 알림장 100건의 `input.classAnnouncement`를 조회하여 검색할 수 있다. 전체 알림장에서 임의로 공지를 추측하여 추출하지 않고 분리 저장된 전달사항만 쓴다. 텍스트만 남은 과거 기록에서는 공지 구분을 보장할 수 없어 자동 추출하지 않는다. 필요한 자료는 교사가 직접 양식으로 등록한다.

## 추가 설정 (이번 작업에서는 운영 DB/배포 변경 안 함)

1. 기존 공지 테이블이 없으면 Supabase에서 `docs/class-announcements.sql`을 적용한다.
2. `docs/notice-templates.sql`을 적용하여 제목·분류 및 본인 양식 수정 RLS를 추가한다. 기존 본문·소유자·기록은 삭제하지 않는다. 서버는 로그인 사용자 ID로 모든 조회·수정·삭제를 제한하고 `user_id`는 클라이언트 입력에서 받지 않는다. 다른 사용자 비공개 자료는 공유하지 않는다.
3. 선택 사항: [한국천문연구원 특일 정보](https://www.data.go.kr/data/15012690/openapi.do)의 활용 신청 후 서버 환경변수 `KOREAN_HOLIDAY_API_KEY`에 **디코딩된** 인증키를 넣는다. 브라우저 공개 변수나 소스 코드에 넣지 않는다. `getRestDeInfo`를 작성일과 이어지는 3일의 연·월로 조회한다. 공휴일·대체공휴일·설날·추석 명칭은 API 응답을 사용하며 특정 연도 날짜를 하드코딩하지 않는다. 월별 결과는 메모리에 6시간 캐시한다. 키 없음·4초 시간 초과·응답 오류는 일반/주말 인사로 대체한다. 공휴일이 기관 휴원일임을 가정하지 않는다.
4. 기존 기관 지역·날씨 조회 연동이 없어 실제 날씨 자동 조회는 제공하지 않는다. ‘오늘의 날씨 인사’는 일반 후보로 대체하고 교사가 확인한 날씨를 직접 적도록 안내한다. 날씨 미연동은 생성·저장에 영향을 주지 않는다.

## 검증

- `node --test tests/*.test.cjs tests/*.test.mjs`: 기존 기록·권한·사진·Word·문장 순서·알림장 회귀 테스트 포함.
- `node tests/notice-browser.cjs`: 실제 RecordWizard를 격리된 로컬 Next 테스트 환경에서 렌더링한다. 설치된 Chrome을 이용하며 모든 서비스 호출은 모의 처리한다. 관찰 입력 재사용, 빈 영역, 공지 다중 선택·수정·해제·저장·재사용·원본 수정·삭제, 작성일 추천 변경, 일반 인사 대체, 문장 이동, 최종 미리보기/저장/Word 일치와 모바일 화면을 확인한다. 테스트 런타임과 스크린샷은 `.qa/`에만 생성한다.
- `npm run lint`, `npm run build` 및 TypeScript 검사.
- 새 모델에 실제 관찰을 보내는 테스트, 운영 Supabase 마이그레이션/RLS 실행, 공휴일 API 실인증 조회, 실서비스 배포는 수행하지 않았다. 운영 DB 설정과 외부 서비스 실연동은 적용 전에 별도로 확인해야 한다.
