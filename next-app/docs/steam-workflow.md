# STEAM 적용하기

## 실제 앱과 진입

Next.js 실제 앱의 퀵메뉴 선택지에 `steam`을 추가했다. 회원 홈의 네 칸 구성과 기존 선택지는 그대로 유지한다. 화면은 `/records/steam`, 사진·관찰 분석은 `/api/steam/analyze`다. Streamlit에는 연결하지 않는다.

기본 연령은 만 2세이며 만 0~5세로 변경할 수 있다. 사진 올리기 → 관찰 더하기 → STEAM 읽기 → 놀이 이어가기 → 과정 기록하기 → 근거 더 보기의 하나의 작업 흐름에서 사진·관찰·교사 수정 상태를 공유한다.

STEAM은 아이별 작성이 아니라 놀이 단위로 사용한다. 아이 별칭 입력과 필수 검증은 없으며, 기존 공통 기록 형식과 호환을 위해 내부 `childAlias`에는 식별 정보가 아닌 `놀이 관찰`을 넣는다.

## 기존 저장·녹음 구조 재사용

- 기존 보관 사진은 본인 소유의 `photo_records.id`로 참조한다. 재업로드하지 않는다. 개인 보관함은 기존 페이지 나누기를 유지한다.
- 새 사진은 기존 `preparePhoto`로 EXIF를 제거하고 축소한다. 기존 `/api/photos`와 비공개 `play-photos` 버킷을 사용한다. 최대 5장, 새 사본은 장당 600KB 이하이다.
- 기존 `ObservationRecorder`의 녹음·전사·수정 기능을 그대로 사용한다. 교사가 선택한 전사문은 중복 없이 현재 관찰에 추가하고 `record_fragments.fragment_id`를 보관한다.
- 기존 `/api/records/save`, `play_sessions`, `generated_texts`를 사용한다. v1 저장 envelope에 선택적 `steam` 필드를 추가하므로 이전 기록도 읽을 수 있다. 별도 SQL 마이그레이션은 필요하지 않다.
- STEAM 저장에는 `sourceObservation`, `confirmedObservation`, `interpretation`, `extension`, `process`, `draft`, 선택 영역 및 사진·녹음 참조를 별도 필드로 보관한다. 기존 기록의 관찰·해석·연결 필드에도 동일한 구분으로 전달한다.
- 내 기록에서 STEAM 화면을 다시 열 수 있다. 기존 보관함 사진 참조는 내 기록의 사진 목록과 Word 다운로드에도 반영한다. 삭제된 사진은 제외한다.
- 놀이 이야기 생성에는 교사가 확인한 관찰만 기존 관찰 handoff로 전달한다. 미실행 확장 제안을 사실 입력에 섞지 않는다.

## Childcare Insight에서 참고한 방식

`childcare-insight/lib/normalization/pipeline.ts` 및 `lib/policy-intelligence/analyzer.ts`의 원자료–분석–근거–사람의 검토 분리를 참고했다. 해당 프로젝트를 수정하거나 데이터베이스를 공유하지 않는다.

- 서버에서 교사 관찰 인용문을 원문과 대조하고 문자 시작·끝 위치를 계산한다. 원문에 없는 인용과 잘못된 사진 번호·후보 연결은 카드에서 제외하되 실패 내역은 남긴다.
- 사진 번호와 AI가 제시한 사진 관찰 후보의 연결만 자동 검증한다. 사진의 실제 내용 및 해석 타당성을 자동 검증했다고 표시하지 않으며 `needs_review`로 분류한다.
- 활성 분석의 원출력은 수정 가능한 카드와 별도로 보관한다. 실행 ID, 모델, 프롬프트/스키마 버전, 생성 시각, 입력 해시, 축소·재인코딩한 사진 바이트 해시, 검증 내역을 저장한다.
- 재분석은 새 후보로 제시하고 교사가 반영할 때만 활성 카드를 교체한다. 기존 확인 관찰·해석·제안·과정 초안은 유지한다. 이전 실행은 메타데이터와 해시를 보관하며, 이전 모든 원출력을 누적하는 별도 분석 테이블은 구현하지 않았다.

## 과정 초안과 수정 보호

초안은 확인한 관찰과 교사가 입력한 과정 항목, 선택·수정한 잠정 해석으로 구성한다. 없는 과정은 `[교사 보충 필요]`로 표시하고 미래 관찰 계획은 미실행이라고 표시한다. AI가 없던 과정을 생성하는 추가 호출을 하지 않는다.

초안 재생성 및 해석·지원 계획 가져오기는 기존 글이 있으면 변경을 확인한다. 모든 수정은 저장 확인을 해제한다. 사진·연령·관찰 입력이 바뀌면 재분석과 검토 전 저장을 막는다. 저장 요청에서도 확인 관찰·해석·제안과 기존 기록 필드의 일치를 검증한다.

작성 글은 기존 앱의 브라우저 임시 저장 방식에 맞춰 계정과 작업별로 하루 동안 복원한다. 새 사진 바이너리는 브라우저 저장소에 넣지 않으며 단계 이동·재분석 중 메모리에 유지한다. 저장 전 새로고침하면 사진 재첨부가 필요하다고 명시한다. 저장된 사진은 ID로 다시 연다.

기존 정책에 따라 글 저장 후 새 사진을 보관하고 최종 참조를 갱신한다. 사진별 안정 키로 재시도 중 중복 보관을 방지한다. 사진 저장 또는 최종 갱신에 실패하면 부분 저장 상태를 명시하고 글·선택 사진을 유지한다. DB와 Storage를 묶는 단일 트랜잭션은 없다.

## 외부 연동과 검증 범위

기존 서버 `OPENAI_API_KEY`, `OPENAI_MODEL` 및 Supabase 설정을 재사용한다. AI 요청은 인증·동의·사진 소유권 확인 후 서버에서만 실행하며 `store:false`와 제한 시간을 적용한다. 키·사진 URL·서버 예외 상세를 응답에 노출하지 않는다.

현재 앱에는 학술 검색·초록/원문 확인 서비스가 없다. 근거 더 보기에는 이용 불가 상태와 필요한 연동을 표시한다. Childcare Insight의 정책 수집 결과를 연구 논문으로 사용하지 않으며, 가짜 논문·DOI·링크를 만들지 않는다. 이 연동과 상관없이 분석·과정 기록을 사용할 수 있다.

2026-10-05 검증:

- 관련 테스트 52개 통과: STEAM 근거 검증, API 인증·동의·입력 오류, 소유권, 분리 저장 및 재저장, 기존 사진·녹음·기록·Word 회귀 검증.
- 실제 클라이언트 컴포넌트를 사용하는 Edge 브라우저 테스트: 퀵메뉴 네 칸 유지, 사진 선택, 녹음 연결, 분석 실패·재시도, 결과 수정과 재분석 후보, 수정 보존, 사진 저장 실패·재시도, 저장 후 다시 열기, 연구 이용 불가 상태, 모바일 가로 넘침 없음.
- TypeScript 및 변경 소스 ESLint 검증. Next.js 프로덕션 빌드 검증.
- AI·Supabase는 테스트 fixture로 검증했다. 실제 아동 사진 전송, 유료 AI 호출, 실제 계정의 DB·Storage 쓰기, 물리 마이크 녹음 및 운영 서비스 검증은 실행하지 않았다. main 병합과 서비스 배포는 하지 않는다.

API 구조화 출력은 [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 확인하고 기존 Responses API 호출 방식에 맞췄다.
