# 관리자 기능 이전

## 접속

- `/admin` → 미인증 시 `/admin/login`, 인증 후 같은 사이트의 관리 화면.
- 회원 Supabase 로그인과 별도의 관리자 세션(4시간, HttpOnly, SameSite Strict).
- `ADMIN_ID`, `ADMIN_PASSWORD` 사용. 기존 로컬 설정의 `id`, `password`도 호환.
- 세션 서명은 `ADMIN_SESSION_SECRET` 또는 서버 전용 Supabase 키 사용. 비밀번호 변경 시 기존 서명 무효화.
- 배포 환경에는 동일한 서버 환경변수를 별도로 등록해야 함. 다중 인스턴스 배포에서는 관리자 로그인에 게이트웨이의 공유 속도 제한을 추가할 것. 현재 앱의 1분 5회 제한은 프로세스 단위.

## 기존 Streamlit 기능 대응

| 기존 기능 | 현재 사이트 |
| --- | --- |
| 회원·놀이 세션·사진·생성 문장·이전 기록 조회 | 데이터 관리, 페이지당 50개 |
| 전체·오늘·7일·이번 달 | 한국시간 기준 조회 |
| 운영 수치·유형 분포 | 대시보드 수치와 분포 막대 |
| CSV | 선택한 조건 전체 행, UTF-8 BOM, 수식 주입 방지 |
| 숨김·복구·전체 복구 | 확인 후 실행, 회원 활성 상태도 변경 |
| 영구 삭제 | 별도 확인문구와 재확인, 기존 Auth·사진 정리 규칙 |
| 공지 작성·편집·보관·복구 | 기존 document-v2와 이전 블록 변환, 본문·서식·이미지·첨부파일 |
| 고정·활성·예약 | 공지 페이지 및 첫 화면 고정 공지 반영 |
| 이미지 팝업 | 대상·순서·위치·기간·링크, 최대 3개, 오늘 닫기 |

기존 데이터 테이블과 Storage 버킷을 그대로 사용한다. Streamlit 원본 코드는 보존했다.
파일 업로드 직후 아직 저장하지 않은 신규 파일은 Storage에 남을 수 있다. 게시물 저장 후 교체·제거된 기존 파일은 정리한다.
영구 삭제는 여러 서비스(DB/Auth/Storage)에 걸친 비원자적 작업이다. 일부 실패 시 오류를 표시하므로 목록을 다시 조회하고 남은 대상을 확인한다.

## 검증

- `npx tsc --noEmit`, `npm run lint`, `node --test tests/*.test.mjs`
- `node --env-file=.env.local tests/admin-browser.mjs`: 로컬 관리자 로그인만 실제 처리. 데이터 숨김·공지 저장은 모의 응답. 관리자 계정/비밀번호를 출력하지 않음.
- 운영 데이터에서는 로그인, 데이터/통계/공지/팝업 조회, 비인증 401 차단만 확인. 실제 삭제·복구·게시·업로드는 실행하지 않음.
