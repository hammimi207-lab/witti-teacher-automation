# 사진 보관과 AI 활용 확인

2026-09-19 기존 Streamlit 동작과 Next.js 서비스 비교 및 복원 결과.

## 확인한 차이

- Streamlit은 `play-photos` 비공개 버킷과 `photo_records`를 사용하고, 본인 사진 목록과 삭제 기능 및 보호자·기관 지침 확인 체크를 제공했다.
- 기존 Next.js는 브라우저의 File을 생성 요청과 미리보기에만 사용했다. Word는 사진 안내문만 넣었고, 저장 요청에는 사진을 전달하지 않았다.
- Next.js의 시험 이용 비밀유지·개인정보 동의는 유지되고 있었다. 이 동의와 생성 시 AI 활용·아동 사진 활용 확인은 목적이 달라 별도로 유지한다.

## 현재 동작

1. 생성 전에 AI 전달·교사 검토 확인을 받는다. 사진이 있으면 보호자 동의와 기관 지침 확인도 요구한다. 기본 체크는 하지 않는다. 생성 API에서도 현재 버전과 확인 여부를 검증한다.
2. 브라우저 및 서버에서 사진을 JPEG로 다시 인코딩해 EXIF를 제거하고 크기를 줄인다. 원본 파일은 변경하지 않는다.
3. 저장 전 Word는 현재 첨부 사진을 포함한다. 종합 기록 저장 시 사진 사본도 보관한다. 관찰 언어만 저장하거나 저장하지 않기를 선택하면 사진은 저장하지 않는다.
4. 동의 버전, 문구, 서버 저장 시각을 저장 기록에 포함한다. 부분 사진 저장 실패 시 완료로 표시하지 않고 재시도를 안내한다.
5. 마이페이지는 최근 기록과 내 사진 관리 기능을 제공한다. 기존 사진도 동일한 사용자·세션 관계로 조회한다. 기존 사진을 다른 계정으로 자동 이관하지 않는다. 시험 이용 동의가 만료되어도 로그인한 본인은 마이페이지에서 사진을 삭제할 수 있다.
6. 사진 조회 API는 본인 소유를 매번 검사하며 공개 주소를 발급하지 않는다. 응답에 private/no-store를 사용한다. 기록에서 다운로드할 때도 새로 조회한다.
7. 사진 삭제 시 저장소의 이미지 바이트를 삭제한다. 최소한의 삭제 표시는 재시도로 사진이 복원되지 않도록 유지하고, 파일명·별칭·캡션은 제거한다. 기록 삭제는 사진 삭제와 별개다. 이미 내려받은 Word와 사용자 기기의 원본까지 삭제하지는 않는다.
8. 사진은 사용자가 직접 삭제할 때까지 보관하며 화면에서 이를 안내한다. 저장되지 않은 과거 사진을 복구할 수 있다고 안내하지 않는다.

## 검증

- `node --test tests/photos.test.mjs tests/word-download.test.mjs tests/record-preview.test.mjs tests/record-delete.test.mjs tests/confidentiality.test.mjs`
- `npm run build` 및 변경 파일 ESLint.
- `node .deploy-tools/check-photo-storage.cjs`는 저장소·테이블 호환성을 실제로 검증한다. 임시 계정 두 개와 단색 합성 사진만 생성하고 종료 시 정리한다. 다른 계정의 API 접근, 직접 Storage 접근, 직접 테이블 조회가 모두 차단됨을 확인했다.
- Word ZIP 내부에 사진 바이트가 실제로 포함되는지, 사진 비율과 표 그리드, 삭제 후 새 다운로드에서 사진이 제외되는지 검사한다.

테스트에서 실제 아동 사진을 AI에 전송하지 않았다. 동의 UI·접근 제어 복원은 법률 적합성 인증을 의미하지 않는다.

## 2026-09-19 Word 다운로드 재발 수정
- 실제 최근 다운로드 파일의 표 grid가 100/100이고 정상 파일은 3060/7140인 것을 확인했다. 이전 클라이언트 생성 코드가 사용된 파일이다.
- 생성 완료 화면과 저장 기록의 WordDownload를 공통 POST /api/records/word 서버 출력으로 변경했다. 서버는 최신 표 양식으로 매번 생성하며 캐시하지 않는다.
- 저장 기록 사진은 사용자 소유의 현재 미삭제 행에서만 읽고, 저장 전 사진은 요청에 첨부하여 문서에만 포함한다. 다운로드로 사진을 저장하거나 AI에 전송하지 않는다.
- 표 너비/테두리, 과거 기록, 교사 해석/지원 계획, 사진 및 삭제 반영 등 29개 관련 테스트와 ESLint, production build 통과.
- 새 다운로드 경로를 사용하려면 이미 열린 화면은 내용을 저장한 뒤 한 번 새로고침해야 한다. 이미 내려받은 문서는 재다운로드가 필요하다.
