# Streamlit → Next.js 기능 이전 기준

기존 `streamlit_app.py`는 전환 완료 전까지 운영 기준본으로 유지한다. 각 기능은 **화면 → 검증 → 데이터 → 권한 → 결과 비교**가 모두 통과한 뒤에만 이전 완료로 표시한다.

## 기능 인벤토리

| 영역 | 기존 구현 | Next.js 위치 | 상태 | 완료 조건 |
|---|---|---|---|---|
| 홈·메뉴 | Streamlit tabs | `/` | 1차 완료 | 반응형 메뉴와 주요 진입점 확인 |
| 기록 입력 | 기록 요정 wizard | `/records/new` | 1차 완료 | 연령·유형·교육과정·관찰 검증 일치 |
| AI 생성 | Responses API | `/api/records/generate` | 1차 완료 | 기존 원칙, JSON 결과, 오류 처리 비교 |
| 사진 분석 | 최대 20장 중 3~5장 추천 | 기록 생성 API | 부분 완료 | 품질 점수·추천 이유·저장 흐름 이전 |
| 회원 인증 | Supabase Auth + members | `/login` | 대기 | 로그인·가입·인증·재설정·세션 보호 |
| 기록 보관 | play_sessions/generated_texts | `/records` | 대기 | 사용자 소유권·보관기한·삭제 확인 |
| 사진 보관 | photo_records + Storage | `/records` | 대기 | private bucket·signed URL·일괄 삭제 |
| Word 문서 | python-docx | 다운로드 API | 대기 | 기존 문서 섹션과 한글 글꼴 비교 |
| 공지 | platform notices | `/notices` | 화면 완료 | 예약·대상·첨부·숨김 처리 |
| 방문 팝업 | platform popups | `/` | 대기 | 노출 기간·대상·위치·다시 보지 않기 |
| 관리자 | secrets 로그인 + CRUD | `/admin` | 대기 | Supabase role 기반 서버 권한으로 교체 |
| CSV·통계 | pandas/altair | `/admin` | 대기 | 기간 필터·분포·CSV·복구 기능 |

## 데이터 호환 원칙

### 선택 저장 및 개인 장학 비교표

- 생성 API는 더 이상 DB에 기록을 쓰지 않는다. 생성 결과는 화면에만 두고 `/api/records/save`에서 로그인 사용자의 명시적인 저장 요청을 처리한다.
- 놀이 이야기·알림장 모두 종합 기록 앞에 원문 / 더 정확한 관찰 언어 / 1차 개선 내용 비교표를 표시한다. 관찰 근거가 부족한 정보는 보충하지 않도록 지시한다.
- 종합 기록과 관찰 언어는 개별 저장한다. 생성 UUID별 기존 `play_sessions.session_id`를 재사용하고 `generated_texts.result_text`의 version 1 JSON에 저장 선택, 입력 문맥, 결과를 보관한다. 사진 원본은 저장하지 않는다.
- 내 기록은 두 분류 탭에서 최근 100개, 본인 소유, 미삭제, 미만료 기록을 표시한다. 기존 일반 텍스트 및 이전 JSON도 읽으며 기존 기록을 삭제하거나 일괄 변경하지 않는다.
- 코드 검사·빌드 및 로컬 테스트 통과. 실제 Supabase 쓰기 권한/스키마와 로그인 후 저장·조회 왕복은 별도 실사용 검증이 필요하다.

### 2026-09-04 화면 변경

- 새 기록의 일지 선택지와 홈 안내만 숨겼으며 기존 일지 스키마와 기록은 유지한다.
- 놀이 이야기 생성 결과에 기존 놀이명, 추천명 3개, 사진·관찰 근거, 추천 이유와 교사 성찰 팁을 추가했다. 원래 입력명을 자동 덮어쓰지 않는다.
- `/temperature`: 첨부된 감성 일기·3줄 요약 양식을 이전했다. 현재 메모리 내 생성과 텍스트 다운로드만 제공하며 DB 저장/기록 조회는 아직 이전하지 않았다. 직접 입력 점수는 기존 36.5 기준을 유지하고 화면에 표시한다.
- `/admin`: 메뉴 및 권한 보호된 읽기 전용 현황 화면을 추가했다. Supabase Auth의 서버 관리 `app_metadata.role === "admin"`을 확인하며 `user_metadata`는 신뢰하지 않는다. 관리자 역할을 자동 부여하지 않는다. 집계는 로그인 계정의 RLS 범위에 제한되며 CRUD·CSV·복구는 미이전이다.
- 확인: ESLint, TypeScript/production build, `node --test tests/record-recommendations.test.mjs` 4개 통과. 브라우저에서 일지 미노출, 감성 일기 생성, 3줄 계산(37.4℃), 관리자 비로그인 안내 확인. 실제 AI 사진 생성 및 관리자 인증 후 DB 집계는 미검증이다.

- 기존 Supabase 프로젝트, 테이블명, Storage bucket을 우선 재사용한다.
- 실제 스키마를 확인하기 전에는 migration SQL을 실행하지 않는다.
- 모든 사용자 데이터 쿼리는 `user_id`와 RLS를 함께 적용한다.
- 관리자 권한은 브라우저 입력값 비교가 아니라 회원 profile의 `role`을 서버에서 확인한다.
- 사진 원본은 공개 URL로 만들지 않으며 private bucket과 짧은 signed URL을 사용한다.
- 기존 자동 삭제 예정일(`expires_at`)과 soft delete(`deleted`) 의미를 유지한다.

## 단계별 검증

1. 같은 입력을 기존 앱과 새 앱에 넣는다.
2. 필수값, 경고 문구, 선택 가능한 교육과정 영역을 비교한다.
3. AI 결과에서 허구의 대화·감정·발달 단정이 없는지 확인한다.
4. 저장 전후 테이블 row와 사용자 소유권을 확인한다.
5. 모바일, 데스크톱, 키보드 접근을 확인한다.
6. 통과 결과를 이 문서 상태 표에 반영한다.
